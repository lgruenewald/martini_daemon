Topology Trajectory
===================

Molecular dynamics trajectories typically include only atom positions
and periodic box vectors, as those are most relevant for analysis tasks.
Various formats may also include velocities, forces, energies, various
thermodynamic variables as well. Atom (or bead if Martini-specific) names,
types, or bonds may be included as additional topological metadata,
facilitating analysis and visualization, but there is typically no support
for changing this metadata as the simulation goes. Since Martini Daemon
concerns itself with changing (reactive) topologies, a new format,
the topology trajectory, was designed to store dynamically changing
topology metadata about the simulation. These files have the ``.toptraj``
file extension.

The ``.toptraj`` files generated by Martini Daemon's
:doc:`/autoapi/martini_daemon/TopTrajReporter` contain the following information:

* Atom names, types, charges, masses, for each frame.
* Additional static topology information, such as the list of initial molecules at the start of the simulation,
  as well as residue names and IDs.
* The bond graph for each frame. This is basically a list of bonds, without the force field specific information,
  and with at most one bond connecting any two atoms. Virtual sites are also included. They are represented as several
  bonds, each connecting one of the constructing atoms to the virtual particle. The mass of virtual sites is 0,
  so they can still be identified.

The following Python classes can be used to interact with this format:

* :doc:`/autoapi/martini_daemon/TopTrajReporter`
* :doc:`/autoapi/martini_daemon/TopTrajWriter`
* :doc:`/autoapi/martini_daemon/TopTrajReader`

Additionally, a VMD plugin can be found at the ``vmd_plugin`` directory
in the git repository, which contains its own reader implementation in C.

This file format supports compression to reduce file sizes, and can be memory
mapped for fast access and on-demand per-frame decompression, enabling
fast and memory efficient sequential or random access. Writing is optimized
only for sequential writes. A full description of the file format
is found at the end of this document.

Making trajectories whole
-------------------------

Martini Daemon provides a minimal CLI for using ``.toptraj`` files to make trajectories whole, using the following
syntax:

::

    daemon whole -i out.xtc -o whole.xtc -s out.toptraj

Topology analysis
-----------------

This subsection details one possible analysis task, using the bond network,
and mapping it to bonds between monomeric units.
This can be used to analyze oligomer or polymer topologies (finding chains, loops, cycles, ...).
The script below reads ``.toptraj`` files and constructs a bond network between
monomers, rather than between individual atoms (beads).
Note, that by doing so, there can be more than one bond between a pair of monomers,
so do verify whether this behavior is correct.
By default, in the .toptraj format, duplicate bonds are removed only between the
same pair of atoms (beads).

::

    #!/usr/bin/env python3
    from martini_daemon import TopTrajReader
    import networkx as nx
    import numpy as np

    def read_monomer_graph(bond_frames: list[list[tuple[int, int]]], mapping: np.ndarray):
        """Map a list of bead-bead bonds to monomer-monomer bonds."""
        # input data and uninitialized result
        # make a mapping atom -> monomer
        monomer_frames = []
        for frame in bond_frames:
            # bonds that are between different monomers
            monomer_frames.append(
                np.array([
                    (mapping[p1], mapping[p2])
                    for p1, p2 in frame
                    if mapping[p1] != mapping[p2]
                ], dtype=np.uint32)
            )
        return monomer_frames


    atom_per_monomer = 5
    n_monomer = 100
    n_atoms = n_monomer * atom_per_monomer

    mapping = np.arange(n_atoms, dtype=np.int32) // atom_per_monomer

    r = TopTrajReader("out.toptraj")

    bonds = []

    while (f := r.read_frame()):
        # read while f is not None
        bonds.append(read_monomer_graph(f.bonds, mapping))
    # after all frames were read, r.read_frame() returns None

    n_frames = len(bonds)

File format specification
-------------------------

Note the following first:

* Strings are encoded as a uint8 representing the string length, followed by
  raw bytes (UTF-8 encoded). Writers should truncate longer strings to be at most 255 bytes.
* Integers are always little endian in this format, and their signedness and size is always specified.
* Floats are 32 bit IEEE 754 floats.
* Doubles are 64 bit IEEE 754 floats.

The binary layout of the file can be divided into three sections:

* Magic number
* Per-Simulation data
* Per-Frame data

The magic number must be the following eight bytes:

* The byte c0
* The ASCII string "TOPTR"
* The major version of the format, uint8 (currently 1)
* The minor version of the format, uint8 (currently 0)

Per-Simulation data and Per-Frame data is organized into chunks: one chunk
for per-simulation data, then one chunk for each frame within the file.
Each chunk is laid out in the file as follows:

* Size of the compressed chunk on disk, compressed, in bytes, uint64
* Size of chunk data, decompressed, in bytes, uint64
* Compressed chunk using zlib, including a zlib header at the start for compression details
* CRC32 of (decompressed) chunk data, uint32

The remainder of this section describes the layout of the data within the chunks.

The per-simulation data chunk contains the following layout:

* Simulation name (string)

* Number of initial molecule types (Number of entries in the ``[molecules]`` directive), uint32

* For each initial molecule type:

    * Name (string)
    
    * Number of molecules (uint32)
    
    * Number of atoms (beads) per molecule (uint32)
    

* Number of atoms (uint32)

* For each atom:

    * Resname (string)

* For each atom:

    * Resid (uint32)

The per-frame data contains the following layout:

* Frame number (uint32), must be one more than previous frame, must be 0 for first frame

* Number of atoms (uint32), must be same as in per-simulation data

* Simulation step (uint64)

* Simulation time (double)

* For each atom:

    * Atom (bead) name (string)

* For each atom:

    * Atom (bead) type (string)

* For each atom:

    * (Partial) charge (float)

* For each atom:

    * Mass (float)

* Number of bonds (uint64)

* For each bond:

    * Index of first bonded member (uint32)

    * Index of second bonded member (uint32)
